# Icecream Problem — 逆向分析与自动化记录

对 [softserve.nog.cc](https://softserve.nog.cc/) 这款「挤冰淇淋堆高」小游戏的逆向分析记录：
从读懂它的物理判定开始，到用自动化程序把成绩从 **48cm 推到 248.6cm**。

> 个人娱乐用途的研究记录。仓库不包含游戏任何原始代码。

## 成绩

| 阶段 | 成绩 | 手段 |
|---|---|---|
| 人工基线 | 48 cm | 手动操作 |
| 参数调优 | 56.6 cm | 自动化 + 网格搜索 |
| 高速大圈 | 90.5 cm | 找到 `stroke` 隔离机制 |
| 常规路线极限 | **103.9 cm** | 同机制调到极值 |
| `dropBelow` 捷径 | **213.7 cm** | 绕过分层隔离 |
| 三角形 + 自转 | 217.3 cm | 离散跳点提高捷径频率 |
| 大半径 + 定高收手 | **248.6 cm** | 塔宽增加 + 在临界前按高度停手 |

最终记录 **248.6 cm**，约为原始成绩的 5.2 倍。瞬时最高摸到 261.1 cm（松手后倒塔，不计入记录）。

## 游戏机制一句话版

高度只增不减；每次落点要么被限速地走（每帧 0.031 单位），要么被直接挂到塔顶（每层 +0.306 单位）；
塔在累计倾角达到 `toppleLean = 1.2` 时倒塌。所有策略本质上都在做两件事：**让每帧都走第二条分支**，以及**在倾角攒满之前收手**。

详细判定链见 [docs/mechanics.md](docs/mechanics.md)。

## 三条路线

### 1. 常规堆叠（稳定，硬顶 ~104cm）

落点每帧最多移动 `extrusionLengthPerSecond × dt × 2.5 = 0.031` 单位。
系统只把 `stroke` 差值 ≥ `neighboringStroke = 0.72` 的旧点当作支撑，所以要让一层「独立」，需要积累 0.72 的 stroke —— 即 **0.38 秒/层**。

高速大圈（快速旋转让 `stroke` 迅速累积）能把速度提到 5.4cm/s，但塔在约 19 秒后因倾角累积倒塌，两者相乘锁死在 104cm 附近。

```bash
# 稳定配置（成功率约 2/3）
python src/synth_model.py 0.51 0.28 -0.08 0 0.10 19.2 1.1 run1 999 0 0 0 0 0 0 1
```

### 2. `dropBelow` 捷径（快，混沌，130~230cm）

当目标点离塔的弯曲轴线超过 `creamDiameter/2 × missShift = 0.45` 时，游戏不再「慢慢堆」，而是直接找塔上能接住的最高点挂上去，并一次性把 `stroke` 推 0.72。把旋转周期压到 0.03 秒，每帧都满足该条件，于是绕过了 0.38 秒/层的隔离限制。

```bash
# 冲刺配置（约 22cm/s，但每次落在 130~215 的哪一段看运气）
python src/synth_model.py 0.51 0.03 -0.11 0 0.10 9.0 1.1 run1 999 0 0 0 0 0 0 1
```

**这条路线是混沌的。** 相位 `2πt/0.03` 对帧时刻极度敏感，不到 0.1ms 的抖动累积几十帧后完全去相关，同一组参数每次运行的轨迹都不同。

### 3. 三角形 + 自转 + 大半径 + 定高收手（248.6cm）

圆的落点是连续变化的，指针追上目标后两者的水平距离会缩回 0.45 以下，`dropBelow` 就断了。**多边形把目标点变成离散跳变**：三条边长为 `1.732 × R`，每次换顶点都是一次远超触发的瞬移。

但纯三角形会**卡死**——三个方位固定，塔柱也在同样的方位长起来，一旦目标点与柱子的水平距离超过 0.36，`dropBelow` 的 `√(1−(d/u)²)` 项趋零，再也挂不上去（实测 4 秒冲到 116cm 后页面高度完全冻结）。让三角形整体缓慢自转可以绕开这个死锁。

半径同样关键。`dropBelow` 的触发用的是落点每帧的位移，混合后的位移随边长线性增长，`R = 0.51` 时是 0.467——只比 0.45 高一点点，触发率约 74%；`R = 0.66` 时是 0.605，触发率升到 94%，塔也因此更宽、能长到更高。

```bash
# 最终配置（约 30cm/s，完成率约 1/6）
python src/synth_model.py 0.66 0.0167 0.05 0 0.10 30.0 1.1 run1 246 0 0 0 0 0 0 -3 0.35
```

末尾参数：`-3` 是负的 `liss`（正三角形），`0.35` 是自转角速度（rad/s）；`246` 是 `stopCm`——**到达该高度立即松手**。

**收手判据是最后一个关键。** 塔的倾角是逐层累加的，越高越贴临界。等影子模型崩溃（`modelfail`）或页面停滞（`stall`）再收手，等于等到塔已经没有余量，松手后的振荡会直接推倒它。改成到固定高度立刻收手，塔还有时间在 1.5~3.5 秒内晃稳，成功率显著提高。

成功带在 **244~246cm**，`stopCm` 设到 250 以上时塔常常长不到就饱和了。

**只有三角形成立**：四边形边长 0.72 却 0.6 秒停滞，五边形 139cm，六边形 27.8cm。切顶点频率也不能降——改成每两帧切一次立刻死在 10.7cm。半径也有窗口：R=0.68/0.70 会因为落点超出 `rimPosition` 的 0.671 钳制而退化。

## 已排除的方向

以下都被实测否定，记录在此以免重复：

- **质心反向补偿**：只多 2cm，且引入振荡
- **李萨如轨迹**（扫圆盘提高挂载命中率）：塔寿命掉到 4~7 秒，最高 142
- **倾角反馈**（`alpha` ±2/5/10）：全部落在混沌分布的正常区间
- **底座加固**（先慢速夯底座再冲刺）：寿命延长到 12 秒，但前期损失过多，最高 173
- **阶跃切换**（稳定堆到 104 后切冲刺）：切换后 1 秒内必塌
- **piling / 静止堆叠**：增速仅约 1cm/s
- **多边形边数 > 3**：四边形混合位移理论最高（0.673，高于三角形的 0.615），但页面实测 0.0cm——一个点都没堆起来；五边形 139，六边形 27.8
- **双点（N=2）**：13 帧混合缓冲在两点间交替时两项反向抵消，位移只剩两点距离的 0.2 倍，上限 0.264（阈值 0.45）；三种切点周期实测 76.4 / 42.4 / 26.1
- **小半径圆**：落点每帧位移约等于 `R`，够不到 0.45 触发线（R=0.35 → 1.4cm，R=0.45 → 137cm）；且 `stroke` 增速也正比于位移，每层路径长到会被 stall 判据误杀
- **反向自转**：0.88 秒停滞，1.1cm
- **切顶点降频**（每两帧一次）：10.7cm
- **本轮轨迹**（慢速大圆 + 快速小圆维持挤出）：落点每帧位移仅 0.027，触发率 0%
- **松手前回中收尾**（想让 `finish` 不启动）：240/259/222，全倒

共约 **230 组**配置。

## 两个方法论陷阱

**帧率必须守住 60fps。** 页面物理按 `fixedDt = 1/60` 累积，帧率掉到 50fps 以下时物理步会被丢弃，成绩假性塌陷一半。测过一次：CPU 被其他进程抢占，帧间隔从 6.3ms 涨到 17~21ms，同一套参数从 217cm 掉到 48~93cm。用 `--disable-gpu-vsync --disable-frame-rate-limit` 启动浏览器可隔离此问题。

注意这不是「帧率越高越快」——解锁到 3400fps 与 158fps 成绩一致，只是不能**低于** 60fps。

**停手信号决定成败。** 塔的倾角逐层累加，越高越贴临界，所以「什么时候松手」比「挤多快」更能决定记录有没有。三种信号的实测完成率：

| 信号 | 触发时机 | 完成率 |
|---|---|---|
| `stopCm`（到指定高度） | 塔仍有增长余量 | **约 1/6**，但能拿到最高分 |
| `modelfail`（影子模型先判倒） | 塔已到临界 | 约 2/3 |
| `stall`（页面停滞 0.6s） | 塔已饱和 | 约 1/6 |

`modelfail` 完成率高，但它出现的时候高度已经被钉死了；`stopCm` 成功率低，却允许把高度设到临界点上再收手，最终成绩更高。

**stall 判据会误杀慢速轨迹。** 运行器用「页面高度 0.6 秒没涨」判定停滞并松手。但 `stroke` 的增速正比于落点每帧位移，每层所需时间因此正比于 `1/R`——R=0.15 时约 0.67 秒一层，比窗口还长，于是正常的慢速堆叠被当成停滞、提前结束，表现成 `0.0 ~ 1.2cm` 的「死局」。

判据：看影子模型的 `generated`。真正的 0.0 局 `generated` 只有 `0.045`（36 个物理步 ≈ 0.6 秒），说明对局只跑了 0.6 秒就被停手；放宽窗口到 3 秒后同参数能堆到 23cm 才倒。**任何「小半径/慢速」方向的测试结论，先确认窗口不是瓶颈。**

**离线模型会骗人。** 用从 bundle 提取的物理类离线跑，结算阶段**每次都成功**——圆周 `p=0.03` 停 9.5 秒能到 280cm 完成。但页面上同一配置从未超过 214cm。页面的帧时刻抖动会放大混沌，离线只能用来筛选候选轨迹，不能用来预测成绩。

## 复现说明

运行器通过 Playwright 驱动真实浏览器，向 `#operation-area` 合成 `PointerEvent`，并按圆周轨迹逐帧下发坐标。同时把从页面 bundle 中提取的物理类作为影子模型并行运行，用于实时读取高度、倾角、质心等状态。

**本仓库不包含游戏的原始代码或其提取物**（`sim_core.js`）。`sim_run.js` 与 `experiments/` 下的脚本依赖它才能离线运行；运行器 `synth_model.py` 则需要自行准备。

## 参数速查

| 参数 | 含义 |
|---|---|
| `R` | 轨迹半径（单位：内部单位，1 单位 = 5cm） |
| `p` | 旋转周期（秒） |
| `oz` | 轨迹圆心的 z 偏移 |
| `alpha` | 倾角反馈增益 |
| `maxShift` | 反馈最大偏移 |
| `stopT` | 固定停手时刻（秒） |
| `stopCm` | 达到该高度即停手 |
| `beta` | 倾角变化率阻尼 |
| `ccGain` | 质心回中增益 |
| `p2` / `pT` | 时变周期目标值 / 过渡时刻（负值启用阶跃） |
| `liss` | z 轴频率比（≠1 时为李萨如轨迹）；**负值 = 正 N 边形**（`-3` 为三角形） |
| `spin` | 多边形整体自转角速度（rad/s），仅当 `liss` 为负时生效 |
